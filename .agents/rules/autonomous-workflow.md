# 🤖 Autonomous Execution & Sub-Agent Workflow Rules

## 1. 核心运行原则 (Core Principles)
- **Zero Interruption (零中断)**: 任务开始后，严禁在中间步骤询问“是否继续”、“请确认”等交互语句；必须端到端自主执行至全部验收通过。
- **Action-Oriented (行动优先)**: 优先使用内置工具（Read/Write Files, Terminal Commands, Search）直接解决问题，而不是输出口头方案。
- **Evidence-Based Done (客观闭环)**: 任务完成的判定必须依赖命令退出码（Exit Code 0）及测试/编译结果，而非主观假设。

---

## 2. 虚拟子代理调度模型 (Sub-Agent Role Play)
遇到复杂需求时，在内部自主切换以下三个虚拟角色并按序流转：

1. **[Planner Agent] 任务拆解与初始化**
   - 快速分析依赖与影响范围。
   - 在项目根目录创建或更新 `TASK_LIST.md`，将大需求拆解为原子级（Atomic）子任务清单。
   - 任务格式：`- [ ] [模块名] 具体执行项`。

2. **[Coder Agent] 增量开发与实施**
   - 严格按照 `TASK_LIST.md` 的顺序逐项执行。
   - 每完成一个原子任务，立即将 `TASK_LIST.md` 对应项更新为 `- [x]`。
   - 遵循最小修改原则，严禁盲目大范围重构无关代码。

3. **[QA & Fixer Agent] 自动化验证与自愈**
   - **执行自检**：主动运行项目的类型检查（TypeScript）、Linter 及单元测试。
   - **错误自愈**：若命令报错或测试失败，直接读取报错日志自主修复，严禁将报错抛给用户；最多自主重试 3 次，若仍失败则在日志中记录原因并回滚至稳定状态。

---

## 3. 自主执行约束与死循环熔断 (Safety Guardrails)
- **死循环防护**：同一文件连续修改超过 3 次未通过测试时，暂停盲目改动，重新阅读全局依赖关系再行动。
- **环境安全**：严禁自主执行不可逆的高危命令（如 `rm -rf /`、强制重置未提交分支等）。
- **完成输出**：当且仅当所有子任务打钩且自检通过后，输出最终成果摘要（改动文件列表、验证命令执行结果）。
